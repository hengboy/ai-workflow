# Project memory

## Standards

- The workflow authorities are `.ai-workflow/AGENTS.md`, which holds the complete project workflow contract, and `.ai-workflow/notes/README.md`, which holds the note governance; the workflow contract lives there rather than being restated here, so this file carries only the project's current product, repository and meta standards.
- The complete project workflow contract lives in `.ai-workflow/AGENTS.md`, single-sourced from `templates/project/AGENTS.md`, and applies to the entire project and every participating agent. Host installation only adds one short loading entry between `<!-- ai-workflow:begin -->` and `<!-- ai-workflow:end -->` in each global instruction file (opencode `~/.config/opencode/AGENTS.md`, claude `~/.claude/CLAUDE.md`, codex `~/.codex/AGENTS.md`), single-sourced from `templates/contract/AGENTS.md`; that entry requires an explicit read of the project contract and never assumes that a host recursively loads hidden directories or follows Markdown links. A missing project contract is reported with the `ai-workflow init <project-root> --upgrade` entry instead of a global fallback. Root-level `AGENTS.md`/`CLAUDE.md` stay user-owned; there is no `update` subcommand and no `.ai-workflow/project-manifest.json`; `ai-workflow init` writes `MEMORY.md`, `.ai-workflow/**` and `.gitignore`.
- This repository tracks `.ai-workflow/**` and `MEMORY.md`; only `.ai-workflow/plans/` and `.worktrees/` are gitignored, and it ships no root `AGENTS.md`/`CLAUDE.md`, so agent guidance exists only in the user-level loading entry and the project contract.
- Adopted projects refresh exactly five generated workflow documents from the fixed upstream source `hengboy/ai-workflow` branch `main`. The fixed allowlist in `src/sync/artifacts.ts` (`generatedArtifacts`, `generatedDocumentError`, `validateGeneratedSnapshot`, `hasLegacySectionMarker`) maps `templates/project/AGENTS.md` to `.ai-workflow/AGENTS.md`, `templates/project/notes/AGENTS.md` to `.ai-workflow/notes/AGENTS.md`, `templates/project/notes/README.md` to `.ai-workflow/notes/README.md`, `templates/project/notes/implemented/AGENTS.md` to `.ai-workflow/notes/implemented/AGENTS.md` and `templates/project/notes/archived/AGENTS.md` to `.ai-workflow/notes/archived/AGENTS.md`, and `ai-workflow sync [project]` and `ai-workflow init --upgrade` replace them as complete files: a differing markerless target is overwritten by design, an absent one is created and an identical one skipped. Root `MEMORY.md` is project-owned and init-only — a fresh `init` writes a local skeleton only when it is missing, and sync and upgrade never replace, append, normalize, compare or migrate it — with no ownership markers, no section parsing and no `src/sync/merge.ts`; `templates/project/MEMORY.md` is only the init-time local bootstrap scaffolding. A generated target that still carries legacy `ai-workflow:section` markers is refused with its path and a manual-replacement instruction before any write, and the five-file source must be a complete markerless snapshot at one immutable commit: `src/sync/source.ts` acquires the templates with a shallow temporary clone of the fixed public address `https://github.com/hengboy/ai-workflow.git` branch `main`, pins one immutable 40-hex commit, reads no token or credential file, uses no GitHub CLI or SSH configuration and removes the temporary directory before returning; on macOS only, when none of `https_proxy`, `HTTPS_PROXY`, `all_proxy` or `ALL_PROXY` carries a value, the default runner reads the enabled static system proxy through a bounded `scutil --proxy` and copies `https_proxy` (`http://` CONNECT) or `all_proxy` (`socks5h://`, IPv6 bracketed) into the child git environment while preserving caller `no_proxy`/`NO_PROXY`, and an absent, disabled, invalid or failed helper leaves ordinary Git behavior with no global environment, Git configuration or host setting changed, so a missing, unreadable or still-marked member yields `unverified` with `verified: false`, `proceed: true` (exit 2) and zero target writes. `src/sync/index.ts` (`applyTemplateSnapshot`, `synchronizeProject`, `reconcileIgnoreFile`, `notesStructureDirectories`) holds the shared publication core, which `upgradeProject` reuses with the shipped local templates and a null source commit, so local upgrade reports `needs_attention` with an unverified local-source warning and makes no upstream freshness claim while retaining its missing-prerequisite conflict and its exact guard that refuses legacy decision-record instructions before any write. Statuses and exit codes are `synchronized` 0, `unverified`/`needs_attention` 2 and `pending`/`conflict`/`failed` 1; `--check` proposes without writing, structural conflicts write nothing, and a publication failure restores invocation-local originals and removes only invocation-created artifacts. Synchronization stores no baseline, keeps generated navigation, the archive manifest and note triplets preserved, and performs no Git operation. The operator refreshes the managed CLI and host entry commands before converting a project or starting another workflow skill in it. The additive automatic host-triggered entries built on this shared core are described in the next standard.
- OpenCode, Claude Code and Codex share the synchronization core through additive native host entries. `ai-workflow install` registers only owned entries — the auto-loaded OpenCode plugin `.config/opencode/plugins/ai-workflow-sync.js` rendered from `templates/hooks/opencode.js`, and context plus `PreToolUse` hook commands in `~/.claude/settings.json` and `~/.codex/hooks.json` — and every entry invokes `ai-workflow sync-hook --host <host>`; `uninstall` removes only those owned entries and files while preserving unrelated hooks and settings. `src/sync/gate.ts` (`runProjectGate`, `ProjectGateInput`, `ProjectGateOptions`, `ProjectGateResult`) resolves the actual adopted root, runs the synchronization core exactly once for a `PhaseEntry` when a planning, coding or plan-to-tasks skill session starts and stores the complete result in the host runtime cache keyed by that actual root outside the project, serves every native `SessionStart`, `UserPromptSubmit` and `PreToolUse` event from that stored result with zero source requests, returns an `allow` with a visible no-check context and no freshness claim and writes nothing when no valid stored check exists, exempts only its own sync actor and the updated-authority read without clearing a stored ordinary blocker, and maps a report to `allow`, `deny` or `skip`. `src/install/hooks.ts` (`installSynchronization`, `uninstallSynchronization`, `synchronizationPath`, `SynchronizationRecords`) owns the additive install, refresh and uninstall semantics. The CLI `sync-hook` prints the raw gate JSON for the `--phase` form on every host and for the OpenCode stdin gate, emits host-native Claude Code and Codex stdin output (`PreToolUse` deny via `hookSpecificOutput.permissionDecision`; a `UserPromptSubmit` block with a top-level `decision` of `block` and `reason`) that never exposes the raw `allow`/`deny`/`skip` decision, and always exits 0 for handled results; the raw form's top-level `decision` (`allow`, `deny` or `skip`) has `status`, `verified` and `proceed` inside its optional nested `report`, the host follows its own protocol, and the manual `ai-workflow sync` command prints a `SyncReport` with `status`, `verified` and `proceed` and no `decision`. After a safe patch changes the contract, the gate exposes the updated authority for explicit read or injection before ordinary work; `conflict` and `failed` block, and warnings proceed without a freshness claim. The next skill start atomically replaces the stored result, and the manual `ai-workflow sync` command stays a fresh, cache-independent check that never replaces the stored gate decision. Codex hooks require human trust, OpenCode requires a restart, and a disabled, untrusted, unloaded or duplicate host-scoped skill is reported as not active rather than auto-approved; `templates/skills/sync-ai-workflow/SKILL.md` is the shipped safe manual skill and a shadowing host-scoped copy is preserved and reported for one-time resolution, never deleted blindly.
- When documenting architecture or module boundaries, use English structural elements and explicitly name modules, boundaries, ownership and related structural terms; prose language preferences do not translate structural elements.
- `config.yaml` carries only the optional `active_profile` field, install writes skills and role agents byte-for-byte from their templates with no injected prose-language directive, and a leftover `output_language` key is an unknown key that fails configuration validation before any write.
- Navigation exact-path validation accepts a literal `$` segment as a legal filesystem character, so a TanStack Router style route directory such as `apps/case/src/pages/case/detail/$caseId` is indexed and authorized, while `?`, `*`, `[`, `]`, `{`, `}`, `<` and `>` are rejected structural characters; the grammar lives in the exact-path guard of `src/context/validate.ts` and the module-root and known-path guards of `src/context/fallback.ts`. Feature verification resolves a public symbol through a relative `export *` barrel re-export transitively, so an indexed definition reached from a generated barrel stays valid while a `default` export or a non-exported definition still does not resolve from `*`.
- Host agent frontmatter stays host-native and is rendered from each template's `tools:` declaration: Codex uses TOML `model`/`model_reasoning_effort`, Claude uses `allowed-tools`, and OpenCode supports both `v1` (`mode: subagent` with singular `permission:` using `bash`/`task`) and `v2` (`mode: subagent` with ordered `permissions` rules using `shell`/`subagent`) selected by `--opencode-version v1|v2|auto` (`install`/`profile activate` default `auto` via `opencode --version`, library default `v2`), where the template `search` tool maps to `glob` plus `grep`, `web` maps to `webfetch` plus `websearch`, and every role denies nested dispatch (`task` in v1, `subagent` in v2) because only the primary orchestrator dispatches. OpenCode `hidden: true` removes an agent from the subagent catalog and blocks the `subagent` tool, so no dispatchable role may set it; that catalog requirement is guarded by `tests/behavior/opencode-agent-contract.test.ts`.
- `MEMORY.md` records only the project's current standards and behavior: the change that supersedes a statement rewrites it to the current state or removes it in the same change, so the recorded standards stay current as changes land; superseded history belongs to Git and Agent Notes, never to `MEMORY.md`. This standard lives in `.ai-workflow/AGENTS.md` (its `## Shared context and maintenance` section), the `documentation-maintainer` role template, the init bootstrap `templates/project/MEMORY.md` and `README.md`.
- Shipped workflow prompt templates use a mandatory tone: normative statements use `must`, `required`, `never` or `only`, the soft hedges `should`, `consider`, `try to`, `when it improves` and `if possible` are absent, and `may` appears only in genuine permission or optional-field contexts. This standard lives in the shipped prompt templates and `.ai-workflow/notes/implemented/process/2026-10-18-skill-prompt-deduplication.md`.
