# Project memory

## Workflow contract and host integration

- The workflow authorities are `.ai-workflow/AGENTS.md`, which holds the complete project workflow contract, and `.ai-workflow/notes/README.md`, which holds the note governance; the workflow contract lives there rather than being restated here, so this file carries only the project's current product, repository and meta standards.
- The complete project workflow contract lives in `.ai-workflow/AGENTS.md`, single-sourced from `templates/project/AGENTS.md`, and applies to the entire project and every participating agent. Host installation only adds one short loading entry between `<!-- ai-workflow:begin -->` and `<!-- ai-workflow:end -->` in each global instruction file (opencode `~/.config/opencode/AGENTS.md`, claude `~/.claude/CLAUDE.md`, codex `~/.codex/AGENTS.md`, antigravity `~/.gemini/AGENTS.md`; Antigravity's `~/.gemini/GEMINI.md` is never touched), single-sourced from `templates/contract/AGENTS.md`; that entry requires an explicit read of the project contract and never assumes that a host recursively loads hidden directories or follows Markdown links. A missing project contract is reported and routed by actual adoption state instead of a global fallback. Root-level `AGENTS.md`/`CLAUDE.md` stay user-owned; there is no `update` subcommand and no `.ai-workflow/project-manifest.json`; `ai-workflow init` writes `MEMORY.md`, `.ai-workflow/**` and `.gitignore`.
- Setup recovery selects the entry point from actual adoption state after explicit user authorization: a project with no existing adoption uses ordinary `ai-workflow init <project-root>`, which creates the contract, `MEMORY.md` and navigation rather than requiring them first; an existing adoption with its `.ai-workflow/` directory, `MEMORY.md` and both navigation files uses `ai-workflow init <project-root> --upgrade`; missing prerequisites return exact paths without overwriting local data, and the preflight or directory presence never authorizes setup. This standard lives in `templates/skills/setup-ai-workflow/SKILL.md`, `templates/project/AGENTS.md` and its `.ai-workflow/AGENTS.md` mirror, `templates/contract/AGENTS.md`, `templates/skills/planning/SKILL.md`, `templates/skills/coding/references/workspace.md` and `README.md`.
- This repository tracks `.ai-workflow/**` and `MEMORY.md`; only `.ai-workflow/plans/` and `.worktrees/` are gitignored, and it ships no root `AGENTS.md`/`CLAUDE.md`, so agent guidance exists only in the user-level loading entry and the project contract.
- The project contract's state-domain matrix is the common authority for delegated execution `done`/`blocked`/`failed`, review verdicts, test observations, the two implementation-record statuses, checkpoint events and workspace-readiness reports, gate decisions, the six `SyncReport` statuses and the seven locator results. These domains stay distinct, no successful-looking value authorizes a later gate, and review acceptance and test observations are explanatory categories rather than new serialized values. The contract also retains every distinct obligation, exception, evidence path and recovery path without a fixed character, line, byte or reduction quota; report-body targets remain distinct from contract length while the source contract and its tracked mirror stay byte-identical. This standard lives in `.ai-workflow/AGENTS.md` (`## State domains and progression` and `## Shared context and maintenance`) and its delivered semantics rationale lives in `.ai-workflow/notes/implemented/process/2026-11-02-workflow-semantics-context.md`.

## Synchronization and gates

- Adopted projects refresh exactly five generated workflow documents from the fixed upstream source `hengboy/ai-workflow` branch `main`. The fixed allowlist in `src/sync/artifacts.ts` (`generatedArtifacts`, `generatedDocumentError`, `validateGeneratedSnapshot`, `hasLegacySectionMarker`) maps `templates/project/AGENTS.md` to `.ai-workflow/AGENTS.md`, `templates/project/notes/AGENTS.md` to `.ai-workflow/notes/AGENTS.md`, `templates/project/notes/README.md` to `.ai-workflow/notes/README.md`, `templates/project/notes/implemented/AGENTS.md` to `.ai-workflow/notes/implemented/AGENTS.md` and `templates/project/notes/archived/AGENTS.md` to `.ai-workflow/notes/archived/AGENTS.md`, and `ai-workflow sync [project]` and `ai-workflow init --upgrade` replace them as complete files: a differing markerless target is overwritten by design, an absent one is created and an identical one skipped. Root `MEMORY.md` is project-owned and init-only — a fresh `init` writes a local skeleton only when it is missing, and sync and upgrade never replace, append, normalize, compare or migrate it — with no ownership markers, no section parsing and no `src/sync/merge.ts`; `templates/project/MEMORY.md` is only the init-time local bootstrap scaffolding. A generated target that still carries legacy `ai-workflow:section` markers is refused with its path and a manual-replacement instruction before any write, and the five-file source must be a complete markerless snapshot at one immutable commit: `src/sync/source.ts` acquires the templates with a shallow temporary clone of the fixed public address `https://github.com/hengboy/ai-workflow.git` branch `main`, pins one immutable 40-hex commit, reads no token or credential file, uses no GitHub CLI or SSH configuration and removes the temporary directory before returning; on macOS only, when none of `https_proxy`, `HTTPS_PROXY`, `all_proxy` or `ALL_PROXY` carries a value, the default runner reads the enabled static system proxy through a bounded `scutil --proxy` and copies `https_proxy` (`http://` CONNECT) or `all_proxy` (`socks5h://`, IPv6 bracketed) into the child git environment while preserving caller `no_proxy`/`NO_PROXY`, and an absent, disabled, invalid or failed helper leaves ordinary Git behavior with no global environment, Git configuration or host setting changed, so a missing, unreadable or still-marked member yields `unverified` with `verified: false`, `proceed: true` (exit 2) and zero target writes. `src/sync/index.ts` (`applyTemplateSnapshot`, `synchronizeProject`, `reconcileIgnoreFile`, `notesStructureDirectories`) holds the shared publication core, which `upgradeProject` reuses with the shipped local templates and a null source commit, so local upgrade reports `needs_attention` with `proceed: true` and an unverified local-source warning, makes no upstream freshness claim, and its exit 2 alone is not an execution failure while retaining its missing-prerequisite conflict and its exact guard that refuses legacy decision-record instructions before any write. The default template clone is bounded at a fixed 60,000 ms (`defaultCloneTimeoutMs`) for the default runner: a clone killed by that bound, or a timeout-like rejection from an injected runner, raises `TemplateSourceTimeoutError`, so `src/sync/index.ts` returns `failed` with `verified: false`, `proceed: false` and a reason naming the clone operation, the fixed source address `https://github.com/hengboy/ai-workflow.git`, branch `main` and the timeout or killed process, and the gate denies that phase, while an ordinary non-timeout source failure keeps the `unverified` warning continuation with `proceed: true`. Statuses and exit codes are `synchronized` 0, `unverified`/`needs_attention` 2 and `pending`/`conflict`/`failed` 1; `--check` proposes without writing, structural conflicts write nothing, and a publication failure restores invocation-local originals and removes only invocation-created artifacts. Synchronization stores no baseline, keeps generated navigation, the archive manifest and note triplets preserved, and performs no Git operation. The operator refreshes the managed CLI and host entry commands before converting a project or starting another workflow skill in it. The additive automatic host-triggered entries built on this shared core are described in the next standard.

## Workspace and coding execution

## Review and reporting

- Shipped workflow prompts state one portable report contract: a delegated result keeps the `## Output checklist` Markdown shape and targets the whole report body at most 1,200 Unicode code points for an ordinary success and at most 3,000 for a review, failure or blocked result, including `### Summary` and `### Evidence`, with a non-BMP character counted as one code point. Complete findings take precedence over the length target, a missing recoverable reference leaves acceptance unresolved with a visible exception instead of dropping known status, verdict, SHA, exit-code or blocker facts, and a fresh read-only digest grants no write permission, never replays a completed side effect and never claims to remove content already received. Each role reads only its role-scoped context; the primary reads the current-phase task bodies rather than eagerly reading future tasks, child-manifest or note bodies or the entire navigation JSON, the referenced frozen task supplies the canonical exact read/write scopes instead of both scope lists, a no-plan direct or mechanical unit carries its complete explicit scope, and unreadable or contradictory sources block before edits without broader whole-repository discovery or a frozen-input rewrite. These are portable prompt instructions, not a host-enforced runtime cap. This standard lives in the nine shipped role templates, `templates/skills/coding/SKILL.md`, `templates/skills/coding/references/workspace.md`, `templates/project/AGENTS.md` and `.ai-workflow/notes/implemented/process/2026-10-19-prompt-context-transport.md`.
- Coding Spec Review is requirement-only and static: `templates/agents/spec-review.md` judges frozen requirements against an immutable `base_commit`/`head_commit` using Git Operator's complete raw diff and needed committed source and test blobs. A recheck additionally receives the immediately preceding reviewed `previous_head`, its blobs and the separate repair diff, plus affected requirement references and repair scope. It never receives plan or task files, implementer narratives, runtime test artifacts, earlier findings or verdicts, suggested conclusions or conversation history. Both axes complete their initial assigned coverage and use separate permitted payloads at the same head, with the primary retaining runtime-test evidence and mapping original findings to independent recheck observations. `templates/skills/coding/references/review.md` supplies the four role/mode packets, provenance classification and closure procedure; the project contract owns the bounded repair budget and acceptance gates. Planning remains a draft-document review with previous and repaired drafts for a recheck, never fictional commits. The rule is aligned in the coding and planning skills, workspace reference, project contract and README.
- Standards Review keeps MEMORY and notes consistency and reviews delivered logic and boundary correctness, security risk, redundancy and key comments. Each logic finding supplies an exact path or symbol, a concrete supported trigger, caller reachability, observable impact, expected behavior grounded in a public contract, documented use, invariant or required standard, and a correction. A reachable defect is a merge-blocking error even when rare. Security requires a plausible threat under the actual trust boundary with impact and exploitability; speculative or unreachable concerns are not actionable findings, and necessary missing context requires bounded support. Non-defect redundancy and key-comment improvements remain advisory with a minimal behavior-preserving correction and durable rationale. Rechecks compare the previous and current reviewed heads and retain factual finding labels and versioned check evidence. The role remains read-only and limited to authorized paths, immutable source context, standards and supplied evidence, without search, Git, tests or invented requirements. This standard lives in the Standards role, coding skill, project contract, README and `.ai-workflow/notes/implemented/process/2026-11-05-review-evidence-and-shared-skills.md`.
- Standards Review's delivered-code judgment includes a maintainability lens over confusing naming, an abstraction that hides the data flow, unclear ownership and a context load that forces a new maintainer to reconstruct non-obvious intent. Each maintainability finding names an exact path or symbol and the concrete context cost and stays advisory unless it causes a defect, while a naming or formatting preference without that cost is not a finding; the lens adds no review axis, trigger, gate or role. This standard lives in `templates/agents/standards-review.md`, `templates/project/AGENTS.md` with its byte-identical mirror `.ai-workflow/AGENTS.md`, `README.md` and `.ai-workflow/notes/implemented/process/2026-11-17-planning-decision-quality.md`.

## Operator tooling

## Notes, memory and documentation

- `MEMORY.md` records only the project's current standards and behavior: the change that supersedes a statement rewrites it to the current state or removes it in the same change, so the recorded standards stay current as changes land; superseded history belongs to Git and Agent Notes, never to `MEMORY.md`. This standard lives in `.ai-workflow/AGENTS.md` (its `## Shared context and maintenance` section), the `documentation-maintainer` role template, the init bootstrap `templates/project/MEMORY.md` and `README.md`.
- Shipped workflow prompt templates use a mandatory tone: normative statements use `must`, `required`, `never` or `only`, the soft hedges `should`, `consider`, `try to`, `when it improves` and `if possible` are absent, and `may` appears only in genuine permission or optional-field contexts. This standard lives in the shipped prompt templates and `.ai-workflow/notes/implemented/process/2026-10-18-skill-prompt-deduplication.md`.
- When documenting architecture or module boundaries, use English structural elements and explicitly name modules, boundaries, ownership and related structural terms; prose language preferences do not translate structural elements.
- The notes archive baseline is implemented by `src/notes/archive-baseline.ts` (`archiveManifestPath`, `ArchiveManifest`, `BaselineArchive`, `readArchiveBaseline`, `compareArchiveBaseline`), which resolves one immutable Git commit, reads `archived/manifest.json` at the project-relative repository path for a project root, subdirectory or linked worktree, treats a commit without the manifest as legitimately empty and fails an unknown, unreadable or malformed baseline before any write; `validateNotes` and `sealArchive` both consume it, reject any archived path or digest dropped or rewritten since that commit, and keep filesystem-only behavior when `--base` is absent. `package.json` `check:notes` runs `tsx src/cli.ts notes validate --project . --base HEAD` as part of `check`, where HEAD is the local pre-change baseline. The rationale and the separate archive-integrity boundary live in `.ai-workflow/notes/implemented/process/2026-11-02-notes-maintenance-and-archive-validation.md`.

## Navigation and context

- Context loading is role-scoped. Every participating role explicitly loads its repository's full applicable project contract; every non-Spec role also loads `MEMORY.md`. The contract publishes the role matrix: primary orchestration reads the full contract, MEMORY, the complete frozen spec/plan once and current-phase task bodies; File Explorer reads contract, MEMORY, its supplied locator or fallback and catalog as needed; Researcher reads its research objective and authorized inputs plus the full applicable contract and MEMORY; Backend, Frontend, Test, Git Operator and Documentation Maintainer read contract, MEMORY, the current delegated task or step and necessary exact source or evidence; Standards Review reads contract, MEMORY, authorized note standards and immutable review material with no generic navigation bundle; Spec Review reads procedural contract plus only its mode-authorized requirement, draft or raw-evidence inputs with no MEMORY/navigation bundle; authorized index maintenance or investigation reads relevant entries or full JSON only for the actual authorized work. `navigation.json` is the authoritative machine index, read only for a needed bounded entry, authorized index maintenance or investigation, or an allowed fallback; primary or discovery uses the catalog to locate a feature and verifies a known feature with the existing locator before source discovery. Read scope is permission, not an eager-read checklist, and no session eagerly reads both navigation files. A verified locator may be supplied with repository, worktree and version provenance and reused only within the same session and repository while that provenance and relevant anchor, authority, index and task content stay current; a relevant change or uncertainty invalidates reuse, a fresh session never counts the parent's read as its own, and a role without shell requests the primary to arrange lookup. Missing or empty index permits explicit frozen plan paths; stale, invalid or ambiguous results need bounded resolution; a hit never expands a write scope; old task scopes containing navigation JSON stay valid. This standard lives in `templates/project/AGENTS.md` and its `.ai-workflow/AGENTS.md` mirror (`## Shared context and maintenance`), `templates/contract/AGENTS.md`, the nine role templates, the `planning`, `plan-to-tasks`, `coding`, `setup-ai-workflow` and `sync-ai-workflow` skills, `templates/skills/plan-to-tasks/references/task.md`, `templates/skills/coding/references/workspace.md` and `README.md`.
- `config.yaml` carries only the optional `active_profile` field, install writes skills and role agents byte-for-byte from their templates with no injected prose-language directive, and a leftover `output_language` key is an unknown key that fails configuration validation before any write.
- The navigation Markdown view is a deterministic catalog of feature id, owner, one existing entry, a short responsibility summary and the locate command that never expands the full symbol, related-file, test or read-scope arrays; `ai-workflow context refresh --project <root> --render-only --write` redraws only that Markdown from the validated JSON, preserving the JSON bytes, staying idempotent and rejecting invalid modes, JSON or index paths with no write, while `refreshNavigationMarkdown` owns the redraw and `renderNavigation` the catalog. The primary delegates shell-based generation, pairing and validation to a shell-capable role with exact generated-artifact write authority, and no additional maintenance command is introduced.

## Distribution and profiles

- Navigation exact-path validation accepts a literal `$` segment as a legal filesystem character, so a TanStack Router style route directory such as `apps/case/src/pages/case/detail/$caseId` is indexed and authorized, while `?`, `*`, `[`, `]`, `{`, `}`, `<` and `>` are rejected structural characters; the grammar lives in the exact-path guard of `src/context/validate.ts` and the module-root and known-path guards of `src/context/fallback.ts`. Feature verification resolves a public symbol through a relative `export *` barrel re-export transitively, so an indexed definition reached from a generated barrel stays valid while a `default` export or a non-exported definition still does not resolve from `*`.
- Host agent frontmatter stays host-native and is rendered from each template's `tools:` declaration: Codex uses TOML `model`/`model_reasoning_effort`, Claude uses `allowed-tools`, OpenCode supports both `v1` (`mode: subagent` with singular `permission:` using `bash`/`task`) and `v2` (`mode: subagent` with ordered `permissions` rules using `shell`/`subagent`) selected by `--opencode-version v1|v2|auto` (`install`/`profile activate` default `auto` via `opencode --version`, library default `v2`), where the template `search` tool maps to `glob` plus `grep`, `web` maps to `webfetch` plus `websearch`, and every role denies nested dispatch (`task` in v1, `subagent` in v2) because only the primary orchestrator dispatches. Antigravity renders Markdown `<role>.md` under `~/.gemini/config/agents/` with `name`, `description`, `tools`, `subagent: true`, `mainAgent: false` and an optional `model` tier, mapping `read` to `read_file`, `edit` to `edit_file`/`write_file`, `shell` to `run_command`/`manage_task`, `web` to `search_web` and `search` to `run_command`/`manage_task`, deduplicated in order with no nested-dispatch tool; the `test` role declares `tools: [read, edit, shell]` so it can author scoped tests directly across hosts; a role that declares a shell tool also renders `commandExecutionPolicy: auto`, so routine project git/build/test commands run without repeated approval while Antigravity still gates irreversible actions. `src/sync/gate.ts` rejects any Antigravity operation targeting an adopted root outside the native `workspacePaths` (including pending managed-file maintenance commits) with an immediate `/add-dir` recovery instead of letting subagents wait on a non-workspace approval, `src/install/verify.ts` warns on duplicate directory-form `<role>/agent.md` (case-insensitive) shadow copies beside managed `<role>.md` agents without deleting them, and the contract/skill prompts require Antigravity dispatch to pass `Workspace: "inherit"`, pass exact file paths rather than inlining large files into `invoke_subagent`/`send_message`, avoid concurrent multi-part `send_message` bursts, and kill finished subagent sessions via `manage_subagents`. OpenCode `hidden: true` removes an agent from the subagent catalog and blocks the `subagent` tool, so no dispatchable role may set it; that catalog requirement is guarded by `tests/behavior/opencode-agent-contract.test.ts`, and the Antigravity rendering contract by `tests/behavior/antigravity-agent-contract.test.ts`. `schemas/profile.schema.json` defines Antigravity's `model` as the closed tier enum `inherit|flash_lite|flash|pro` and a concrete model ID fails validation before any write; a tier of `inherit` omits the key from the rendered agent, and `reasoning_effort` is schema-accepted but never rendered, so `activateProfile` in `src/install/index.ts` reports a non-blocking activation warning instead of failing. `src/ops/doctor.ts` and `src/host/smoke.ts` resolve Antigravity readiness and smoke through the `agy` executable (`agy --version`, `agy -p <prompt> --mode plan`), and `doctor` always reports `warn` because it verifies neither authentication nor trust.
- Managed skills are installed only in `~/.agents/skills`; Codex and OpenCode discover that shared directory, Claude Code uses its supported `~/.claude/skills` directory link to the same physical tree, and Antigravity stays single-sourced through one owned `~/.gemini/config/skills.json` entry with the absolute `<home>/.agents/skills` path and a sorted `include_only` list, copying or symlinking nothing under `~/.gemini/` and never writing a `~` path that Antigravity does not expand. Host agent definitions remain native per host. `src/install/hooks.ts` compares resolved synchronization-skill paths before warning about a competing host copy, so a shared link is not a shadow installation; the Antigravity shadow paths it checks are `.gemini/config/skills/`, `.gemini/skills/` and `.gemini/antigravity-cli/skills/`, which are preserved with a warning naming the exact path. Removing host copies or nested backup trees requires explicit local cleanup authorization; installation neither recreates them nor deletes unrelated user skills. `tests/install/sync-hooks.test.ts` covers link recognition and reinstall behavior, and `tests/behavior/review-dispatch.test.ts` checks the role-specific prompt examples as static instruction evidence, not live model compliance.
