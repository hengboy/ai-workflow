# Agent Note: Portable prompt transport and deterministic document maintenance

Status: implemented

English | [中文](2026-10-19-prompt-context-transport.zh.md)

## Problem

Delegated coding transported fixed and repeated context inefficiently. Role reports had no shared size target, so a sub-agent could return an unbounded body that the primary then absorbed, and no surface required an author self-check or stated how to behave when a complete evidence reference was missing. Packets repeated both the relative and the resolved scope lists, and no shipped rule told a primary to read only the current-phase task bodies instead of eagerly reading future tasks. The project contract had grown well beyond a reviewable core of repeated operational prose, while the navigation Markdown view expanded full symbol, related-file, test and read-scope arrays that made the catalog hard to read. The navigation redraw required a candidate and could not regenerate only the Markdown from validated JSON, and the division between semantic curation and generated artifacts was implicit.

## Decision

- All nine managed role templates and the shared Coding and project guidance now state one report contract over the whole report body: at most 1,200 Unicode code points for an ordinary success and at most 3,000 for a review, failure or blocked result, including `### Summary` and `### Evidence`, with boundary examples one code point above each limit and non-BMP characters counted as one code point, and a required author self-check. Complete findings take precedence over the length target; a missing recoverable reference exposes a visible length exception and leaves acceptance unresolved; known status, verdict, SHA, exit-code and blocker facts are retained; and a fresh read-only digest grants no write permission, never replays a completed side effect and never claims to remove content already received. The shipped text states plainly that these are portable prompt instructions, not a programmatically enforced runtime cap.
- The primary reads its own fixed context once and, for split and workspace plans, inspects the frozen schedule, verified workspace status and the current-phase task bodies instead of eagerly reading future tasks or child-manifest and note bodies. The referenced frozen task supplies the canonical exact read/write scopes rather than the packet repeating both scope lists, each leaf self-reads its own fixed context and frozen inputs, and a unit without a frozen plan carries its complete explicit scope. Unreadable or contradictory frozen sources block before any edit, without broader whole-repository discovery or a frozen-input rewrite.
- The source contract `templates/project/AGENTS.md` and its tracked mirror `.ai-workflow/AGENTS.md` are compacted to at most 60% of the captured pre-implementation code-point baseline while every distinct routing, ownership, Git/worktree, synchronization, review, recovery and context obligation is retained. Common leaf rules stay in the core, primary-only workspace and coding detail is referenced from the shipped Coding skill and its workspace reference, and the two files remain byte-identical with the five managed synchronization targets unchanged. The retained-obligation map records every original distinct obligation against its retained authority: the change-routing classes, the class-only review trigger, aggregate repair with one targeted recheck, worktree confinement, the synchronization preflight, the notes-governance pointer, the durable-artifact identifier prohibition, navigation JSON authority, the single implementation record, Git Operator exclusivity, the fresh-sub-agent session boundary, host-native role frontmatter and the MEMORY currency rule remain in the core or the referenced Coding authority.
- The navigation Markdown view becomes a deterministic catalog of feature id, owner, one existing entry, a responsibility summary of at most 120 code points before escaping and the locate command, and never expands the full symbol, related-file, test or read-scope arrays. `ai-workflow context refresh --project <root> --render-only --write` is added as a mutually exclusive alternative to `--candidate` that validates the current JSON and both index paths before atomically regenerating only `navigation.md`, preserving the JSON bytes and idempotency for the same input, with no discovery fallback or whole-index rebuild.
- Maintenance is deterministic: Documentation Maintainer prepares semantic navigation candidates and bilingual prose, and the primary delegates the existing shell-based generation, pairing and validation commands to an existing shell-capable role with exact generated-artifact write authority; no role tool set expands and no additional maintenance command is introduced. MEMORY records current standards and necessary references rather than delivery transcripts.

## Alternatives considered

- **Enforce the report limits at runtime.** Declined: the workflow ships portable prompt instructions with no host interception, so a runtime cap would be an unsupported claim; the honest alternative is stated guidance plus an author self-check and an explicit exception path.
- **Drop the length target when a full reference is missing.** Declined: discarding findings to hit a size target would hide blockers and completed side effects, so complete findings keep precedence and the unmet protocol stays visible with acceptance unresolved.
- **Keep the full contract and only regenerate Markdown.** Declined: the repeated operational prose is the transport cost the change targets, so a catalog-only redraw would not bound the core contract; the contract keeps every distinct obligation while referencing primary-only detail.
- **Redraw Markdown by re-running whole-index discovery.** Declined: a discovery-based redraw would let an unvalidated scan replace curated JSON; the chosen render-only mode preserves JSON bytes and rejects invalid authority without writing.

## Consequences

- Delegated reports, the primary's reads and the maintenance commands are bounded by shipped text; a passing suite proves the guidance is delivered and does not prove live model compliance, a runtime cap or a measured transport reduction.
- The compact contract keeps every distinct obligation in accessible authority: common leaf rules remain in the core, and primary-only workspace and coding detail resolves through the shipped Coding skill and its workspace reference. The source and tracked mirror stay byte-identical and the five synchronization targets are unchanged.
- The catalog keeps JSON authoritative and complete while making the Markdown view concise, and the render-only refresh changes only Markdown with JSON bytes preserved and idempotent for unchanged input.
- [Orchestrator context boundaries in delegated coding](./2026-10-17-orchestrator-context-boundaries.md) keeps its evidence, transport and rebuild decisions; this record adds the whole-body report target, the current-phase read bound and the digest boundary on top of them and partially supersedes only the report and packet guidance that this record now states more completely.
- [Skill and sub-agent prompt deduplication with a mandatory tone](./2026-10-18-skill-prompt-deduplication.md) keeps its duplicate-cluster and mandatory-tone decisions; this record partially supersedes only its limited verbatim duplication approach by standardizing the report contract across every surface, and retains its safety rule that no asserted sentence is dropped without an equivalent replacement.
