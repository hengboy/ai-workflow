# Agent Note: Orchestrator context boundaries in delegated coding

Status: implemented

English | [中文](2026-10-17-orchestrator-context-boundaries.zh.md)

## Problem

Delegated coding could grow the primary orchestrator's context along three vectors with no shipped bound. A delegated sub-agent returned its evidence as full diffs, logs, JSON bodies or code blocks, so the primary absorbed large raw outputs into its own context. Every packet re-inlined the frozen fixed context and the frozen plan files, so each task re-carried content the primary had already read and no leaf was required to read its own repository's context or the frozen files for itself. A checkpointed workspace run had no way to shed accumulated conversation state at a checkpoint, so after an interruption it either kept accumulating context or risked reconstructing state from recollection instead of from the records. Nothing stated an evidence bound, a path-based transport for frozen inputs, or a verification-gated way to rebuild state from disk.

## Decision

- Delegated sub-agent results keep the contractual `## Output checklist` Markdown shape and add upper bounds: each `### Evidence` entry carries the absolute path of the produced artifact or an explicit report reference plus at most one sentence of conclusion, and embedded diffs, logs, JSON bodies or code blocks are prohibited. Large outputs such as test logs, `workspace status` JSON and build output are written to `<plan-directory>/reports/<taskId>.log` — the writing repository's own plan directory, or each repository's slice plan directory in workspace mode — inside the writing leaf's packet-authorized output paths; that reports path is gitignored and never committed. When the primary must digest such an output it dispatches a fresh read-only sub-agent session (for example `file-explorer` bound to the report path, or `test` when a command verdict is required) that returns one bounded conclusion, so the raw content never enters the primary's context. The primary's own output stays at decision level, exempting the handoff copyable prompt, bounded support or recovery requests, and the final report.
- Packets transport the frozen fixed context — the project contract, `MEMORY.md` and both navigation files — and the frozen plan files as absolute paths plus version anchors only: the worktree baseline commit or blob anchor for fixed context and the frozen digest for plan files; content is never inlined. The primary reads the fixed context once at session start as a reusable prefix and does not re-inject content per task, while each leaf explicitly reads its own repository's fixed context and the frozen plan files per the packet contract and, for a plan-referenced indexed feature, runs `ai-workflow context locate --project <root> --feature <id> --verify` and reads the exact paths in its `read_order` output. A full re-injection mode is not provided.
- For a workspace execution with checkpoint records — parent orchestration and slices — the primary may actively rebuild its context only at a clean, fully checkpointed phase boundary or a verified repository delivery boundary, re-deriving state from the frozen schedule, task files, each repository's implementation record and the `workspace status` projection rather than from conversation history. Before continuing it verifies read-only that recorded checkpoint SHAs match Git objects, that `workspace status` shows no drift and that no commit lacks a checkpoint. Discarding context at a dirty or partial phase, a commit-without-checkpoint gap or unknown progress is prohibited; when context pressure appears mid-phase the primary first completes in-flight tasks to the nearest verified boundary and restarts there, and if it cannot reach a clean boundary it reports `blocked` with bounded support. A resumed session follows the frozen schedule and never recomputes the DAG or skips tasks, and ordinary split or unsplit plans keep their existing fresh-session recovery.
- The delivered rule is shipped prompt guidance in `templates/skills/coding/SKILL.md`, `templates/skills/coding/references/workspace.md` and `templates/project/AGENTS.md` with its tracked `.ai-workflow/AGENTS.md` mirror; `MEMORY.md` carries the same standard and the navigation index records this feature with its generated Markdown. No coordinator, phase agent, runtime scheduler or measured performance claim is added.

## Alternatives considered

- **A dedicated coordinator or phase agent holding sub-state.** Declined: the one primary session already owns orchestration, so an extra agent holding sub-state would add a second source of dispatch truth and an unsupported runtime surface without bounding the primary's own context.
- **Full context re-injection, or inlining packet content.** Declined: re-inlining the frozen fixed context and plan files per task is exactly the repeated-read growth this change bounds; absolute paths plus anchors and a read-once prefix carry what a leaf needs without the duplication.
- **A runtime scheduler, remote session or child host process.** Declined: it would add a runtime executor the workflow does not support and cannot verify, while the native parent already dispatches the leaves and owns the frozen schedule.
- **Continuing without a boundary-resume protocol.** Declined: without a verification-gated rebuild an interrupted checkpointed run either keeps accumulating context or reconstructs state from recollection, so recorded progress and SHAs could silently diverge from disk.

## Consequences

- Three shipped rules now bound the three vectors: the coding skill's delegation and precondition guidance, the workspace reference's packet contract and recovery protocol, and the project contract with its mirror. `MEMORY.md` records the standard and the navigation feature names its entries, related files and tests.
- A resumed checkpointed session rebuilds from the frozen schedule, the task files, each repository's implementation record and the `workspace status` projection; it follows the frozen schedule, never recomputes the DAG and never skips tasks, while a dirty, partial, unverified or contradictory boundary stops with a bounded support or recovery request.
- Ordinary split or unsplit plans are unchanged: they keep the existing fresh-session recovery with no active-rebuild rule, and no coordinator, phase agent, runtime scheduler, remote session or child host process is introduced.
- Active rebuild is limited to clean, fully checkpointed phase boundaries or verified repository delivery boundaries, and it is gated on read-only SHA and drift verification before the run continues.
- The shipped-content regressions, CLI validation and documentation checks are delivered-text evidence: a passing run proves the guidance is present and does not prove host runtime enforcement or a measured performance gain.
- [Fresh sub-agent sessions for completed roles](./2026-10-14-fresh-subagent-sessions.md) keeps its completed-session boundary decision; this record does not supersede it and adds the evidence, transport and rebuild bounds on top of the fresh-session rule.
- [Parent workspace coding orchestration](../feature/2026-10-09-workspace-coding-orchestration.md) keeps its activation, worktree, checkpoint and review decisions; this record retains and cross-links it, partially extending its recovery wording with the checkpoint-boundary active rebuild instead of replacing its bounded resume rule.
- [Portable prompt transport and deterministic document maintenance](./2026-10-19-prompt-context-transport.md) partially supersedes this record's report and packet guidance: it standardizes the whole-body report target, the current-phase read bound and the fresh read-only digest boundary, while this record keeps its evidence-bound, path-transport and active-rebuild decisions.
