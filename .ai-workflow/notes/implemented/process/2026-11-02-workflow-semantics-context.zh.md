# Agent Note: Workflow semantics, durable state progression and role-scoped context

Status: implemented

[English](2026-11-02-workflow-semantics-context.md) | 中文

## Problem

已交付契约累积了关于例行委派、评审收口、安装恢复与状态推进的矛盾或未充分定义的表述。它还带有历史上的 60% 与 35,107 码点体量预期，把契约完整性当作长度门槛，并带有普遍急切读取的预期，使每个新会话都加载两份导航文件。这些规则模糊了执行状态、评审判断、测试观察、持久化与导航结果之间的区别，因此一个看似成功的值可能被误当作验收，而必要的条件规则可能为满足配额而被缩短。

## Decision

- 状态语义：项目契约是委派执行、评审判断、测试观察、实施记录完成、检查点与工作区就绪、门控决策、同步报告与定位器结果的共同权威，并为每个域规定所有者、必需证据与允许的下一步动作。技能与角色应用这些定义，同时保留各自独立的义务。
- 例行委派：一个已接受任务可在每个纵向行为边界使用全新的范围明确 Test、实现与验证委派，按需依次进行 RED1、implementation1、GREEN1、RED2、implementation2 与 GREEN2，同时冻结阶段顺序与串行范围任务提交保持不变。预期 RED 指明意图观察到的失败及其实际非零退出，并保留下一步 GREEN 义务；例行切片与验证不消耗也不扩张评审后的修复与复验预算。已完成的会话绝不复用或恢复。
- 评审结果：已完成的评审可报告执行 `done`，而其结论为非 PASS；当每条建议都有有理有据的处理且不存在未解决的阻断项时，允许在建议保持可见的情况下 `PASS`。缺少必需输入为 `blocked`，执行失败为 `failed`，任何看似成功的状态都不能替代验收。
- 安装恢复：实际采用状态选择入口，未采用的项目使用普通 `init`，仅当采用及其前置条件存在时使用 `init --upgrade`。缺少前置条件返回确切路径且不覆盖本地数据，目录存在或预检都不授权安装。
- 无契约配额：契约保留每一条不同的规则、例外、职责、证据与恢复路径，并可按需增长。固定字符、行、字节或缩减百分比都不是验收门槛，历史上的 60% 与 35,107 码点测量属于历史且不是当前门槛，报告正文目标与契约长度保持分离，源契约与其受跟踪副本保持字节一致。契约内容绝不为满足报告目标而被截断。
- 角色限定上下文：每个参与角色加载其仓库完整适用的契约，每个非 Spec 角色加载 `MEMORY.md`，且每个角色加载其已发布矩阵所要求的附加上下文。主编排与发现使用导航目录定位功能，并在源码发现前用定位器校验已知功能，导航 JSON 仅在授权调查或维护或有界的必要条目时读取。读取范围是权限而非急切读取清单；已验证的定位器仅在其来源与相关状态保持当前时可复用；新会话绝不把父级的读取计作自身读取；没有 shell 的角色请求主编排安排查找。
- 已交付界面为 `templates/project/AGENTS.md` 及其字节一致的 `.ai-workflow/AGENTS.md` 副本、契约加载入口、受影响的技能与九个角色模板、`README.md`、`MEMORY.md` 以及精选导航。内容测试是静态已交付文本证据，不证明原生模型合规、运行时强制执行或已测得性能提升。

## Alternatives considered

- **保留历史体量目标作为完整性代理。** 已否决：长度比例无法区分保留的义务与被丢弃的表述，因此可能迫使截断必要规则，或奖励删除而非完整性；保留义务检查与副本一致性才是持久边界。
- **为每个会话保留普遍急切导航加载。** 已否决：它强制无关读取，并与角色矩阵及读取范围权限模型冲突；目录、定位器来源与有界条目规则在不做全面自读的情况下携带所需导航。
- **把各状态域合并为单一成功值。** 已否决：执行完成、评审判断、测试观察、持久化与导航结果具有不同的所有者与证据，合并它们会让检查点或 `done` 报告冒充验收。
- **以每任务每角色一次派发来解决例行委派。** 已否决：每个任务单次角色派发无法承载多个纵向 RED/GREEN 边界，而冻结阶段顺序与串行提交边界已在不设第二次派发禁令的情况下约束工作。
- **仅在技能与角色中应用规则而让契约保持单薄。** 已否决：通用叶子义务必须保留在适用契约中，仅主编排者适用的细节引用自 Coding 权威，因此单薄契约会失去共享权威。

## Consequences

- 契约现在陈述一套一致的状态、评审、安装、委派与上下文规则，且其源与受跟踪副本保持字节一致，同时每项不同义务与条件示例都保留。
- 例行实施可通过全新的范围明确委派一次推进一个纵向切片，而评审收口、阻断项、持久化与工作区就绪保留各自独立的证据要求。
- 导航保持为由权威 JSON 支撑的有界目录，每个角色只加载其矩阵上下文；普遍急切读取预期被移除，同时不降低所要求的契约或 MEMORY 权威。
- 早期记录中的历史 60% 与 35,107 码点测量作为历史保留，不再是验收门槛；当前完整性由保留的不同义务、副本一致性与条件内容检查。
- 已交付内容、安装与 CLI 检查是静态证据。它们不确立三宿主原生合规、运行时修复或已测得的上下文或性能提升。
