# Agent Note: Plan write-scope completeness

Status: implemented

[English](2026-11-16-plan-write-scope-completeness.md) | 中文

## Problem

冻结计划有时会遗漏实现必须创建或修改的文件，尤其是测试、夹具、导出桶、注册接线、受跟踪的生成产物、文档与笔记各侧。执行时要么因阻塞的支持请求停下，要么写出冻结范围之外，导致交付的路径集合不再与计划一致。

## Decision

规划将每个步骤的写入范围冻结为基于仓库证据推导出的完整精确文件清单。清单列出每个创建、修改、删除或重命名的路径，包括行为测试与夹具、预期会变化而需调整的既有测试、导出桶、模块索引、路由或注册接线、schema、迁移、受跟踪的生成产物、文档、navigation、`MEMORY.md`、受影响笔记三元组的每一侧、重命名的两个端点以及每个删除路径。目录、通配符、glob、占位符以及含糊的 "related files" 条目都不是写入范围。每个既有路径都通过定位器或 File Explorer 解析，每个新路径都标记为新文件。

Plan-to-tasks 仅从冻结清单推导每个任务的 `write_scope`。任务写入范围的并集等于其所覆盖计划步骤清单的并集；任务不得加入计划未声明的路径，也不得把精确路径放宽为目录。

首次编辑前，Coding 对冻结范围之外的每个路径分类。支撑路径是位于同一仓库与冻结 AC 边界内的精确路径，不增加用户可见行为、公共接口、配置或依赖、schema 或迁移、跨模块或跨栈契约、安全或隐私边界；例如行为测试、夹具、快照、导出桶或注册项、受跟踪的生成产物、文档、navigation、`MEMORY.md` 或笔记三元组的一侧。Primary 核验并在运行内授权，将其记录到任务提交说明与最终报告，并纳入评审范围，无需单独批准。实质路径——生产源码、公共接口、配置或依赖、schema 或迁移、跨模块或跨栈行为——需要一次有界用户决定；若改变 REQ/AC 或公共契约，则需要新的 Plan ID。每次修订始终只针对一个精确路径；重复或实质修订说明计划存在缺陷，需要规划修复。

## Alternatives considered

- 在任务拆分或编码时自动补入遗漏路径。否决：冻结计划将不再是完整的写入权威，计划也会持续误导。
- 在精确文件未知时允许目录写入范围。否决：目录会授权其下每个文件，重新制造原有的范围溢出。
- 在每个遗漏路径上都阻塞到计划修好。否决：一个附带支撑路径就会拖住整个计划，并造成不必要的重新规划。
- 依赖交付后的 diff 检查。否决：违规已经落地，评审不得不重建预期范围。

## Consequences

规划仍在确认预览与冻结前增加一次审计。单个遗漏的支撑路径不再阻塞整个计划：primary 记录一次精确的运行内修订并继续，修订在提交、最终报告和评审中可见。实质范围变化仍需要一次有界决定或规划修复，重复修订则说明计划不完整。
