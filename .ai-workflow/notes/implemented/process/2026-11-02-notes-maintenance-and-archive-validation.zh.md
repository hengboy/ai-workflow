# Agent Note: Notes maintenance and archive baseline validation

Status: implemented

[English](2026-11-02-notes-maintenance-and-archive-validation.md) | 中文

## Problem

notes 治理存在若干缺口，可能让维护变更在通过结构校验的同时删除或改写历史。已有替代关系评估，但没有要求落地决定的变更处置每一个已识别的匹配，因此已被取代的记录仍可能作为当前指引可达。完全移除条件写得过于简略，没有要求证明生产代码、配置、schema、持久数据或传输数据、迁移与兼容性不再支持该能力。归档校验仍套用 active 正文规则，因此一篇保留旧标题、旧头部或旧章节布局的 archived 记录可能被拒绝，尽管封存历史绝不能被改写成当前格式。归档校验也缺少基于 Git 的保证：自洽的文件系统 manifest 与其归档字节可以被一起重写，因此无法证明后续变更保留了此前封存的路径与摘要。常规项目检查没有直接运行 notes 校验，封存历史漂移因此留在检查之外。

## Decision

- 只对 active note 保留 active 正文格式、语言切换器与结构镜像规则。archived 记录保留其历史标题、空行、切换器、章节以及两侧的旧结构；归档完整性只校验完整三元组、合法路径、`Status: implemented` 状态行及其后紧跟的双语归档日期（该日期不早于文件名日期且两侧一致）、已记录的配对哈希与 manifest 条目。
- 把同变更替代处理视为落地决定的一部分，而不是可选的后续清理，因为推迟处置会让已被取代的记录继续作为当前指引可达，而后续清理可能永远不会发生。新 note 未取代、且理由仍独立有用的相关记录保持 active；只有已确认的完全替代才合并，部分替代保持 active 并建立交叉链接。
- 要求把较早的 feature-addition 记录合并进较晚的 removal 记录并删除时提供完全移除证据：生产代码、配置、schema、持久数据或传输数据、迁移与兼容性不再支持该能力，文档与测试不再声称支持，而残留兼容性或数据会让较早记录作为部分替代保留。
- 把 `--base <commit>` 做成不可变 Git 比较，而不是第二道文件系统校验。命令把 ref 解析为一个提交，通过项目相对的仓库路径读取归档 manifest，使项目根、仓库子目录与链接工作树得到一致结果；缺少 manifest 的提交视为合法的空基准，未知、不可读或格式错误的基准在任何写入前失败。该提交记录的每个归档路径与摘要都必须继续存在且不得改变；后续封存可以追加新条目，但绝不能删除或改写旧条目。
- 把同一检查接入项目检查：`tsx src/cli.ts notes validate --project . --base HEAD`，本地检查以 HEAD 作为变更前基准，而已提交范围或 CI 提供其显式基准。这样默认的文件系统命令仍可在没有 Git 时使用，同时让封存历史漂移在常规检查中可见。

## Alternatives considered

- 把 active 格式与结构镜像套用到 archived 记录。已否决：这样每次 active 格式变化都要改写封存历史，违背字节冻结并破坏历史记录。
- 把每篇相关 note 都视为必须归档。已否决：相关记录在新决定落地后仍可能承载独立有用的替代方案、归属或保证，归档它会移除可达的当前指引。
- 只要存在 removal note 就允许删除较早的 feature-addition 记录。已否决：能力可能仍存在于兼容路径、持久数据或文档中，删除较早记录会隐藏重新引入条件与原始动机。
- 只比较当前文件系统 manifest。已否决：变更可以同时重写归档文件与其 manifest 而仍显得内部一致；Git 基准让变更前的封存成为权威。
- 要求所有 notes 命令都带 `--base`。已否决：新的 notes 树与日常本地撰写必须能在没有 Git 历史时使用，而基准门禁属于交付检查，不是通用撰写要求。

## Consequences

- active note 保持唯一镜像的双语格式，而 archived note 作为封存历史记录继续可读，不再接受 active 格式复验；归档 manifest 对既有条目保持只追加。
- 2026-10-16 的[note 理由与保留记录](./2026-10-16-note-rationale-and-retention.md)被部分取代：其创建标准与保留、归档、删除结果仍然有效，而本记录增加了同变更替代处置与 feature-addition 合并的显式完全移除证据。
- 2026-09-16 的[项目契约与 Agent Notes 记录](./2026-09-16-project-contract-and-agent-notes.md)的归档章节被部分细化：封存机制与字节冻结保持不变，本记录增加了 Git 基准与明确的 archived 格式例外。
- 2026-10-19 的[归档保留评估](./2026-10-19-archive-retention.md)仍然有效且未改变；它决定归档哪些记录，而本记录决定如何强制执行归档完整性。
- `src/notes/archive-baseline.ts` 拥有提交解析、项目相对路径查找与 manifest 比较；`validateNotes` 与 `sealArchive` 都消费它，`package.json` 在 `check` 中运行基准检查。
- 取舍是：使用 `HEAD` 的本地检查只证明已提交的变更前状态，不证明未来提交；不可读的仓库或基准现在会让检查失败，而不是静默回退到文件系统一致性。
