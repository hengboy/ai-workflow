# Agent Note: Project contract and Agent Notes replacement

Status: implemented

English | [中文](2026-09-16-project-contract-and-agent-notes.zh.md)

## Problem

Before this change, ai-workflow wrote the full workflow contract into the global instruction files of all three hosts and used numbered records under `.ai-workflow/adr/` as its proposal and decision mechanism. This caused three concrete problems. First, contract loading depended on host behavior: the project side had no independent, complete, readable authority contract, the global block grew ever longer, and there was no clear repair entry when the contract was missing. Second, the decision records' format, lifecycle, supersession and sealing rules were scattered across role files, skills and the language injection, with no single governance source, so the rules drifted easily. Third, numbered records were immutable after `accepted`, so one record could not express the evolution from proposal to implementation, nor distinguish a current decision from sealed content retained only as history.

This change, under the approved frozen plan `20260916-project-contract-and-agent-notes`, moved the full project contract into `.ai-workflow/AGENTS.md` and fully replaced the previous decision-record mechanism with in-project Agent Notes, with no compatibility path.

## Decision

- The full project contract lives in `.ai-workflow/AGENTS.md`, templated from `templates/project/AGENTS.md`, and explicitly applies to the whole project and every participating agent. Each host's global file keeps only a short loading entry (templated from `templates/contract/AGENTS.md`) that requires the agent to identify the project root and explicitly read the project contract, never relying on the host recursively loading hidden directories or following Markdown links.
- When the contract is missing, report the missing `.ai-workflow/AGENTS.md` and point to `ai-workflow init <project-root> --upgrade` as the repair entry, without falling back to the old full global contract.
- `.ai-workflow/notes/` became the only proposal and decision mechanism. `.ai-workflow/notes/README.md` is the single source for format, lifecycle, supersession and archive governance; `.ai-workflow/notes/AGENTS.md` and each level's AGENTS file provide only entry points and local maintenance boundaries; roles and skills reference the specification instead of copying the full rules.
- `MEMORY.md` records current standards (how) and notes record why, and the two stay consistent in the same change.
- Each note originally used one body language following the existing `output_language`; the `# Agent Note:` title, section headings, field names, `Status` values, paths and dates stayed English, with no translation copies, sidecars or central index. The 2026-09-17 [bilingual note triplet record](./2026-09-17-bilingual-note-triplets.md) superseded that single-language rule: every note now carries English, Chinese and consistency-record siblings, the structural elements remain English, and still no central index is generated.
- The lifecycle is fixed to `proposed`, `implemented`, `rejected`, `archived`, and the classes to `architecture`, `bug-fix`, `feature`, `process`, `simplification`, `testing`. Status must match its directory, and implemented records use Decision and Consequences to describe delivered facts instead of only changing the status line.
- Archiving may only move an implemented record after semantic review, insert the archive date and repair active inbound links; after sealing, the bytes are protected by the digests in `.ai-workflow/notes/archived/manifest.json`. `ai-workflow notes archive --project <root> --seal` verifies all existing entries before atomically appending new ones, writes no manifest on failure, and never rebuilds the manifest to accept modified history.
- Project upgrade uses the explicit entry `ai-workflow init <project> --upgrade`: it requires an existing `.ai-workflow/`, `MEMORY.md` and both navigation files; creates only missing management files and class directories; skips targets that match the template; returns `created` and `skipped`; and when a name conflict exists or a rule file still requires the old record mechanism, reports the exact paths before any write and stops.
- User history is preserved: existing `.ai-workflow/adr/` files, frozen plans, user configuration and existing note bodies are preserved byte for byte, neither deleted nor converted, and they do not enter notes listing, validation or search.

## Alternatives considered

- Keeping a compatibility layer for the old mechanism (commands, aliases, dual writes or a runtime fallback). Declined because the user explicitly required a full replacement with no downgrade code; a dual track would keep two sets of rules as current authority and retain read paths that should be deleted.
- Letting upgrade read and convert historical records automatically. Declined because historical decisions are already frozen, automatic conversion would rewrite user data, and it could present undelivered history as current fact; this change only protects historical bytes and does not read their content.
- Generating bilingual pairs, sidecars or a central index for notes. Declined at the time because the existing language preference needed only a single-language body and extra artifacts would introduce a new drift source and validation surface. The narrower adopted follow-up is the validated consistency record described by the 2026-09-17 [bilingual note triplet record](./2026-09-17-bilingual-note-triplets.md).
- Copying the reference project's decision bodies, legacy-format exemptions and historical archive manifest. Declined because the reference project was used only to understand organization and governance semantics, not as this repository's true record, and copying would fabricate decisions and costs.

## Consequences

- The loading chain became "global short entry → `.ai-workflow/AGENTS.md` → notes specification"; the entry must be read explicitly and host recursive loading is no longer assumed. A project that has the old entry installed but lacks the project contract must run the upgrade first, or project work cannot continue.
- Upgrade gained a new precondition: when `MEMORY.md` or an existing project contract still instructs creating or reading the old record mechanism, upgrade reports the exact file and line and stops, and only a manual merge allows a retry, with no downgrade or bypass mode. This execution explicitly merged the old `MEMORY.md` standard as planned, so the upgrade passed on the first attempt.
- This upgrade created 29 lifecycle and class directories and 6 management files in this project; `created` listed every artifact and `skipped` was empty, and the existing `.ai-workflow/adr/` history, frozen plans and navigation bytes were not rewritten.
- The old mechanism's modules, commands, initialization branch, templates and current instructions were removed wholesale; the published product no longer offers its listing feature, and historical files are only local data that is no longer read. The cost is that historical material is no longer indexed by the tool and must be read manually.
- The semantic correctness of notes still depends on human review: mechanical validation covers only paths, dates, titles, status, required section order, active relative links and archive manifest consistency, and cannot prove that content is truthful or that a decision was delivered.
- Archiving is an irreversible byte freeze: after sealing, modifying, moving or deleting a record, or passing in a modified historical file, is rejected by validate and `--seal`; the cost is that archived notes' outbound links may be stale and are no longer repaired.
- The notes tree was empty at delivery: before this record was added `notes list` returned an empty list, so there were no existing records to preserve, consolidate or cross-link. A later one-time migration on 2026-09-17 completed five existing ADR records into implemented notes and established cross-links, see [migrate retired ADR records to notes](./2026-09-17-migrate-retired-adr-records-to-notes.md); the upgrade itself converted, read or deleted no historical files.
- The single-source and user-history trade-off is explicit: the project contract, the notes specification and the navigation JSON each have exactly one authoritative location, while the user's existing local history files retain their original bytes but are no longer supported workflow inputs.
