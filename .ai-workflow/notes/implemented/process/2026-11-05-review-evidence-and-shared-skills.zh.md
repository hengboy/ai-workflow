# Agent Note: Review evidence and shared skills

Status: implemented

[English](2026-11-05-review-evidence-and-shared-skills.md) | 中文

## Problem

新评审者只拿到原始交付基线和修复后版本时，无法区分已有遗漏与修复回归。通用任务包示例也与 Spec Review 的受限输入冲突。一次修复额度遇到任一种新增缺陷都会停止，而推测性的边界顾虑会在没有证明受支持用法可达的情况下增加工作。本机宿主副本和备份技能树还可能让主代理加载比评审者更旧的委派指令。

## Decision

- coding 评审参考文档为每个轴分别提供首审和复核包。首审即使发现阻塞项也完成已分配覆盖，完整发现优先于报告长度目标。Spec 接收冻结需求与原始证据；Standards 接收适用标准、事实发现和带版本的检查证据。
- 复核保留原始交付基线，并增加紧邻的前次已评审版本、单独的修复差异和必需的不可变文件。评审者指出缺口是在修复前已存在、由修复引入还是来源未知；主代理映射闭环并区分遗漏与未解决发现。定向 PASS 只覆盖其明确的范围与版本。
- 每个边界最多执行两轮修复与复核。第二轮要求具体的范围内修正，以及新缺陷证据或已证明的闭环进展。没有进展、证据不可用、范围变化或额度耗尽时阻止验收；在同一版本补齐缺失原始证据不消耗修复轮次。新会话不得重置额度。
- 逻辑缺陷须证明受支持用法可达，且预期行为来自公开契约、已记录用法、不变量或必需标准。罕见但可达的缺陷仍属于错误。安全判断采用实际信任边界；推测性或不可达顾虑不构成可执行发现。保持行为的冗余简化与持久注释继续按建议处理。
- 技能在 `~/.agents/skills` 下只有一份实体来源。Codex 与 OpenCode 直接发现该目录；Claude Code 使用其支持的个人目录链接指向同一棵树。宿主原生代理仍分别保存。安装器比较真实路径，使共享别名不再被当成遮蔽技能，不创建宿主技能副本或备份树，也不在未经授权时执行破坏性的本机清理。

## Alternatives considered

- **向 Spec 提供实现者的修复叙述。** 不采用，因为修复前后的原始代码足以提供因果证据，无需预设关闭结论或影响独立的需求判断。
- **禁止新增缺陷或允许无限完整评审。** 不采用，因为两者都不能证明交付正确；有界的定向继续保留真实缺陷和明确的停止原因。
- **维护各宿主同步的技能副本。** 不采用，因为分别陈旧的副本曾造成委派输入矛盾。单一实体树消除该版本分歧，并保留 Claude 支持的加载入口。

## Consequences

- `tests/behavior/review-dispatch.test.ts` 检查四种公开提示词示例、证据与来源义务及有界继续；`tests/install/sync-hooks.test.ts` 演练真实文件系统链接和重复安装。这些是静态指令及安装器行为检查，不声称真实评审者始终遵守指令或发现每一个缺陷。
- [Review boundaries and repair](2026-10-14-review-boundaries-and-repair.md) 保留分流、状态与裁决分离、集成保证及历史 smoke 证据；本记录部分替代其修复额度与复核输入决策。[Standards code review](2026-11-02-standards-code-review.md) 保留评审轴归属及维度；本记录细化可达性与发现门槛。两者的独立理由和覆盖限制仍适用，因此保持活动状态并互相链接。
